`parse()` throws a `Silarhi\Caf\Exceptions\ParseException` when:

- the content has no LA44ZZ payment table (fewer than four 121-dash borders), such as an empty string or another file
- a row does not have the expected columns
- a date, in a row or in the header, is invalid or out of range: `13 2021` or `31 02 2021` are rejected instead of
  being rolled over

```php
use Silarhi\Caf\Exceptions\ParseException;

try {
    $paymentSlip = $parser->parse($content);
} catch (ParseException $e) {
    // Not a LA44ZZ payment slip, malformed row or invalid date
}
```

The parser never returns a partial result: one bad row rejects the whole file. Missing metadata is not an error, the
getter returns `null` (see [parsing](/guides/parsing/#metadata)).

## Messages

| Cause                  | Message                                                                            |
| ---------------------- | ---------------------------------------------------------------------------------- |
| No payment table       | `Input CAF LA44 could not be parsed`                                               |
| Malformed or empty row | `CAF Row n°2 could not be parsed`                                                  |
| Invalid date in a row  | `CAF Row n°2 : "13 2025" date value could not be parsed, expected format is "m Y"` |
| Invalid header date    | `"31 02 2021" date value could not be parsed, expected format is "d m Y"`          |

Row numbers count from 1 at the first row of the table, not from the top of the file. An empty table fails on row 1.
